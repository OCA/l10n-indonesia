Core of the SNAP BI (Standar Nasional Open API Pembayaran, Bank
Indonesia) integration for Online Bank Statements.

This module adds the SNAP connection data (Client ID, Client Secret, RSA
key pair) to the online bank statement provider, the SNAP signatures,
B2B access token handling and the standard SNAP *Bank Statement* and
*Balance Inquiry* calls. It does not add any bank by itself: install a
bank module such as ``account_statement_import_online_bca``.

**Adding a bank.** A bank module depends on this module and only
declares its configuration in ``_snap_bank_config()`` (see
``account_statement_import_online_bca``):

.. code:: python

   @api.model
   def _snap_bank_config(self):
       config = super()._snap_bank_config()
       config["mybank_snap"] = {
           "label": "My Bank (SNAP BI)",  # registers the provider service
           "sandbox_url": "https://sandbox.mybank.example",
           "production_url": False,  # typed in on the provider when unpublished
           "channel_id": "12345",
           "token_path": "/openapi/v1.0/access-token/b2b",
           "statement_path": "/openapi/v1.0/bank-statement",
           "balance_path": "/openapi/v1.0/balance-inquiry",
           "history_days": 31,  # optional: older periods are refused / skipped
           "remark_split": 18,  # optional: fixed-width remark parts
           "sandbox_partner_reference_no": "...",  # optional: sandbox-only value
       }
       return config

Its tests reuse the standard SNAP tests:

Configuration
=============

Everything is set on the online bank statement provider of the bank
journal (*Accounting > Configuration > Banks > Online Bank Statement
Providers*, or the *Configuration* button of the journal), tab **SNAP**
(Accounting Manager only):

1. On the bank journal, set the bank account (its number is the
   ``accountNo`` sent to the bank) and *Bank Feeds* = *Online*; choose
   the bank service on the provider, preferably with *daily* statements.
2. Choose the environment (sandbox or production). The Base URL and
   Channel ID are filled in from the bank module; the production Base
   URL must be typed in when the bank does not publish it.
3. Fill in the Client ID, Client Secret and Partner ID
   (``X-PARTNER-ID``) given by the bank.
4. RSA keys:

   - if the bank gives you a key pair, paste or upload the **private
     key** (PEM, also accepted on one line); the public key is derived
     and shown;
   - otherwise click *Generate Key Pair* and send the public key
     (*Download Public Key*) to the bank.

5. Click *Test Token*, then *Test Connection* (balance inquiry).

**Several accounts, one bank application.** Each bank account has its
own journal and provider; the providers of one bank application hold the
same Client ID, Client Secret and private key. The bank keeps one secret
and one public key per application, so after regenerating the key pair
or the secret, update **every** provider using that Client ID. Odoo
warns about the other providers when you change the secret or the
private key.

Secrets (Client Secret, private key, access token) are readable by
Accounting Managers only (the token by system administrators only) and
are never written to logs or messages.

Usage
=====

Statements are pulled by the scheduled action of *Online Bank
Statements* or with *Pull Online Bank Statement* on the provider.
Pulling the same period again never duplicates lines: SNAP has no
transaction id, so each line gets an import id built from account, date,
type, amount and remark, with a counter for identical transactions.

Common SNAP response codes (HTTP status + 2-digit service + 2-digit
case):

- ``401xx00`` / ``4017300`` *Unauthorized (Unknown client / Signature)*:
  the Client ID does not belong to this environment, the private key is
  not the one registered for the application, or the Client Secret /
  Partner ID is wrong.
- ``401xx01`` *Invalid token*: the token is refreshed and the call
  retried once automatically.
- ``403xx01`` *Feature not allowed*: the service is not enabled for the
  application or corporate at the bank.
- ``409xx00`` *Conflict*: duplicate ``X-EXTERNAL-ID``.
- ``429xx00`` *Too many requests / more than 20000 rows*: use daily
  statements.
- ``5xxxx0x``: bank-side error, retry later.
